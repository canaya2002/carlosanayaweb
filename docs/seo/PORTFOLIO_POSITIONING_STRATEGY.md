# Portfolio Domain Positioning Strategy

**Domain:** carlosanayaweb.com
**Purpose:** Engineering portfolio, technical authority, professional reputation
**Companion Domain:** carlosanayaruiz.com (commercial — SEO consulting & web dev services)
**Last Updated:** 2026-04-14

---

## 1. Positioning Thesis

carlosanayaweb.com exists to establish Carlos Anaya Ruiz as a credible, technically deep engineering leader. It is the **reputation layer** -- the domain that answers "Who is this person and why should I trust their expertise?" It is NOT a sales channel. Every page, every piece of content, and every metadata decision must reinforce informational authority and professional identity, never commercial intent.

## 3. Content Pillars

Each pillar represents a thematic area for ongoing content production. Every blog post and project page should map to exactly one primary pillar.

### Pillar 1: Engineering Leadership & Team Management

**Focus:** How to lead engineering teams, scale processes, manage technical debt, mentor developers, and make strategic technical decisions.

**Example topics:**
- How I structure engineering teams for velocity and quality
- The decision framework I use for build vs. buy
- Managing technical debt as a strategic asset
- Mentoring junior developers: what actually works
- Engineering culture: what I've learned building teams

**Target audience:** Engineering managers, tech leads, CTOs, recruiters evaluating leadership capability

---

### Pillar 2: Full-Stack Architecture & Next.js Deep Dives

**Focus:** Detailed technical content about building production web applications, with emphasis on Next.js, React, and modern full-stack patterns.

**Example topics:**
- Next.js 16 App Router: architecture decisions for a bilingual portfolio
- Server Components vs. Client Components: where to draw the line
- i18n in Next.js with next-intl: a complete implementation guide
- Optimizing Core Web Vitals in a Next.js application
- Firebase integration patterns for Next.js applications
- Tailwind CSS architecture for scalable design systems

**Target audience:** Senior developers, architects, developers evaluating Next.js for projects

---

### Pillar 3: AI/LLM Implementation & Orchestration

**Focus:** Practical content about building AI-powered features and products, including LLM orchestration, prompt engineering, and AI assistant development.

**Example topics:**
- Building Nora AI: architecture of an intelligent assistant
- LLM orchestration patterns for production applications
- Prompt engineering for reliable AI outputs
- Evaluating AI model performance for specific use cases
- Integrating AI features into existing web applications
- Cost management for LLM-powered features at scale

**Target audience:** Developers building AI features, product managers evaluating AI capabilities, technical decision-makers

---

### Pillar 4: Cybersecurity in Web Products

**Focus:** Security-first thinking in web development, practical security implementations, and security architecture decisions.

**Example topics:**
- Security headers every Next.js app should have (and why)
- Authentication architecture: what I've learned across projects
- Input validation and sanitization in full-stack applications
- OWASP Top 10 in practice: real examples from my projects
- Security audit checklist for web applications

**Target audience:** Security-conscious developers, DevSecOps professionals, technical auditors

---

### Pillar 5: Project Case Studies & Technical Decision-Making

**Focus:** Detailed breakdowns of real projects, covering the problem, approach, architecture decisions, implementation, and outcomes.

**Example topics:**
- Nora AI: from concept to production AI assistant
- Building a bilingual law firm website with Next.js
- How I chose the tech stack for [project name]
- Database design decisions: when to use what
- Performance optimization case study: achieving sub-second load times
- Migrating from [X] to [Y]: a technical retrospective

**Target audience:** Developers evaluating approaches, hiring managers evaluating depth, peers learning from real implementations

---

### Pillar 6: Career & Professional Growth

**Focus:** Lessons from a career in software engineering, professional development, and the engineering career path.

**Example topics:**
- From developer to engineering manager: what changed
- Building a professional portfolio that actually demonstrates competence
- The certifications that actually mattered in my career
- What I learned getting [specific award/recognition]
- Remote work and engineering leadership: making it work

**Target audience:** Mid-career developers, aspiring engineering managers, career transitioners

## 4. Page-by-Page Positioning

### Home Page

**Role:** Technical identity flagship
**What it must communicate:** Who Carlos Anaya Ruiz is, what he builds, and proof of depth
**Must include:**
- Clear identity statement (name, role, core expertise)
- Areas of technical expertise (NOT services -- see anti-cannibalization rules)
- Featured projects with brief engineering context
- Latest blog posts
- Awards/credentials as trust signals
- Link to commercial domain for consulting inquiries

**Must NOT include:**
- Service listings or service descriptions
- Pricing or engagement models
- "Hire me" or "Get a quote" CTAs
- Commercial testimonials

**Primary keywords:** `"Carlos Anaya Ruiz"`, `"software development leader"`, `"engineering portfolio"`

---

### About Page

**Role:** Professional narrative and credibility builder
**What it must communicate:** Career arc, engineering philosophy, why this profile matters
**Must include:**
- Professional narrative (not just a bio paragraph)
- Career progression with key milestones
- Engineering philosophy / approach to building software
- Awards and credentials as supporting evidence within the narrative
- Education and notable training
- Link to consulting practice at carlosanayaruiz.com
- Social proof (GitHub, LinkedIn, professional associations)

**Must NOT include:**
- Service offerings
- Client list or client testimonials (those belong on commercial domain)
- Consulting rates or engagement details

**Primary keywords:** `"Carlos Anaya Ruiz about"`, `"software engineering leader"`, `"technical leadership background"`

---

### Blog

**Role:** Technical authority hub
**What it must communicate:** Deep knowledge, original thinking, practical expertise
**Content rules:**
- Minimum 1,500 words per post (depth over volume)
- Every post must teach something specific and actionable
- Include code examples, architecture diagrams, or data where relevant
- Each post maps to one content pillar
- Internal links to related projects and other blog posts
- Author bio with Person schema linkage

**Must NOT include:**
- Thin content (sub-500 word posts)
- Sales-oriented content ("why you should hire a consultant")
- Content about ROI of services (that belongs on commercial domain)

**Primary keywords:** Per-post, mapped to content pillars

---

### Projects

**Role:** Case study gallery with engineering depth
**What it must communicate:** Real implementation capability, architectural thinking, problem-solving approach
**Each project page must include:**
- Problem statement: what needed to be built and why
- Technical approach: architecture decisions, stack choices, trade-offs
- Implementation details: notable technical challenges and solutions
- Tech stack with rationale for each choice
- Results/outcomes: performance metrics, user impact, lessons learned
- CreativeWork or SoftwareApplication schema

**Must NOT include:**
- Client testimonials (belong on commercial domain)
- Pricing or project cost information
- "I can build this for you too" messaging

**Primary keywords:** Project name + technical descriptors (e.g., `"Nora AI assistant architecture"`, `"Next.js bilingual website case study"`)

---

### CV Page

**Role:** Professional proof document
**What it must communicate:** Experience breadth, credential depth, career trajectory
**Must include:**
- Work experience with technical accomplishments (not just duties)
- Education and certifications
- Technical skills organized by proficiency
- Awards and recognitions
- Downloadable PDF option
- Scannable format optimized for recruiter review

**Must NOT include:**
- Consulting availability or rates
- "Available for hire" language with commercial framing

**Primary keywords:** `"Carlos Anaya Ruiz CV"`, `"Carlos Anaya Ruiz resume"`, `"software development manager experience"`

---

### Contact Page

**Role:** Professional connection point
**What it must communicate:** Openness to professional connection, collaboration, and technical discussion
**Must include:**
- Contact form for professional inquiries
- LinkedIn and GitHub links
- Clear statement: "For consulting and web development services, visit carlosanayaruiz.com"

**Must NOT include:**
- "Request a quote" language
- Service descriptions
- Consulting packages or pricing

## 8. Summary

carlosanayaweb.com is the credibility engine. It answers every "Who is Carlos Anaya Ruiz?" query with depth, proof, and technical authority. It does not sell. It does not compete with the commercial domain. It builds the trust that makes the commercial domain's conversion rate possible.

Every content decision should pass this test: **"Does this make someone trust Carlos's technical expertise, or does this try to sell them something?"** If the answer is the latter, it belongs on carlosanayaruiz.com.
